万向节锁（Gimbal Lock）GIMBAL LOCK · 自由度丢失演示

文章里那句"绕 Y 转 90° 后，绕 X 和绕 Z 等效，丢掉一个自由度"——这里直接让你转出来看。拖动下面三个滑杆改欧拉角（内旋顺序 X→Y→Z，即 Pitch→Yaw→Roll）。当 Yaw = ±90° 时，Pitch 和 Roll 会变成绕同一根轴转，画面给出死锁高亮。切换"分解视图"看三个环（gimbal）如何退化成两个重合。

GIMBAL · EULER X→Y→Z
—
⚠ GIMBAL LOCK · 丢失一个自由度
X 轴 / Pitch Y 轴 / Yaw Z 轴 / Roll 机头朝向 
// 三种欧拉角旋转矩阵按固定顺序连乘（程序里的做法）
R = Rz(roll) · Ry(yaw) · Rx(pitch)
// 当 yaw = 90°：Ry 把世界 X 轴转到世界 -Z 方向
// 于是"绕 X 的俯仰"与"绕 Z 的横滚"落在同一根轴上 → 多对一 → 死锁
fix: 用四元数 q 表示姿态，q = qz·qy·qx，无顺序退化问题，4 个浮点数还更轻。

两个视角对照 WHY

· 博客园篇：你以为按物体自身坐标系连续转（动态欧拉角），程序却按世界坐标系固定顺序连乘矩阵 → Y90 后 X/Z 轴重合。
· 知乎篇：欧拉角按固定轴旋转与预期三轴自由度是"多对一映射"，Pitch 90° 后 Roll 自由度丢失（陀螺仪船首仰起桶滚失效）。
· 本质同一件事：三个轴的依次应用，在某些角度退化成两个独立方向。

怎么玩这个 demo TIPS

1. 先只拖 Pitch / Roll，看机头灵活转动。
2. 点"一键转到死锁"，再拖 Pitch 和 Roll——画面几乎一样，因为两根轴重合了。
3. 勾"分解视图"看三个 gimbal 环退化成两个共面。
4. 勾"同时显示四元数解"对比：同样的姿态，四元数路径始终有三个自由度。
5. "自动进动演示"复刻文章里的 X90→Y0→180 序列。

流体光影 Hero Section FLUID LIGHT · BLOOM

      
对应 fluid-light 实战篇（一万块的私活成品）。精华不是 A 色切 B 色，而是多个点光源同在、强度各异，由最强的那盏定主色；点击时打乱颜色数组、每盏灯递增 easing 延迟，做出"传送带式依次切换"。这里用 WebGL 片元着色器还原多光源 + 辉光，点画布触发错峰换色。

// 满屏平面 + 多个点光源，用距离场叠出流体感
vec3 col = vec3(0.0);
for (int i = 0; i < LIGHTS; i++) {
  float d = distance(uv, lightPos[i] + flow);
  float falloff = intensity[i] / (1.0 + d*d*8.0);
  col += lightColor[i] * falloff;
}
col += smoothstep(0.6, 1.0, luminance(col)) * bloom; // 辉光
// 换色：每盏灯延迟递增 → 传送带式依次过渡（文章最值钱的机制）

    

  


  
  

    

      
多屏幕同步展示 setViewOffset · 视口切分

      
对应多屏联动两篇（三篇合并增量）。核心是 setViewOffset：一台渲染器把完整画面切给多块屏幕，每块只显示自己那一片；再用 localStorage + storage 事件 做跨窗口统一时钟，让所有屏幕帧同步。下面模拟 4 块屏幕拼一整幅 3D 场景，拖动改分屏数、看每块拿到的视口偏移。

文章里的两个方案 MAPPING

        

          · 方案一 setViewOffset：一份场景多视口切分，适合"一块大画面拆给多屏"的环幕/拼接墙，相机不动、视口偏移。

          · 方案二 多窗口：每屏一个浏览器窗口，用 pageId + localStorage + storage 事件 广播统一时钟和相机状态，各自渲染同一帧；requestAnimationFrame 按统一时间取样，避免各屏漂移。
        

      

      

        
这个 demo 演示了什么 WHY

        

          同一颗旋转的地球/立方体，被切成 N 块视口，每块只画属于自己的 tileX/tileY/tileW/tileH。点"显示完整画面"看未被切分的整幅——对比就明白 setViewOffset 只是"取景框不同"，场景只有一份。真实项目里把这些 tile 换成不同窗口的相机偏移，就是多屏联动。
