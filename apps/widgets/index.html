01 防删除水印 · canvas 平铺 + MutationObserver 守卫

水印是铺满整个区域的 <canvas>，文字、透明度、角度、密度都实时可调。真正的看点在守卫：点「试图删除水印」，MutationObserver 监听到节点被移走，100ms 内自动重建，并记下你失败的次数。

这是一块受保护的演示区。水印层是 absolute 定位的 canvas，盖在内容上，pointer-events: none 所以不影响阅读和操作。

前端水印的老问题是：打开 DevTools 把那个节点一删就没了。MutationObserver 盯住父节点的 childList，谁动了水印就立刻补一个回去——"你删你的，我生我的"。

注意：这挡得住大多数人的手滑，挡不住禁用 JS 的硬核操作；工程上一般还要配合服务端落水印。

    03 手写 Zustand · 30 行的 createStore

    Zustand 的核心就三件事：getState 读、setState 浅合并后广播、subscribe 注册监听。下面两个消费组件（计数器、待办清单）共享同一个 store——任一处 setState，两处自动更新；「外部 setState」按钮证明不挂在组件上也能改状态。先看实现：

    ▸ createStore 实现（约 15 行核心） 
    function createStore(initialState) {
  let state = initialState;          // 闭包里的唯一事实源
  const listeners = new Set();

  const getState = () => state;

  const setState = (partial) => {
    const next = typeof partial === 'function' ? partial(state) : partial;
    state = { ...state, ...next };   // 浅合并，引用替换才算更新
    listeners.forEach((fn) => fn(state));
  };

  const subscribe = (fn) => {
    listeners.add(fn);
    return () => listeners.delete(fn); // 返回退订函数
  };

  return { getState, setState, subscribe };
}

      06 Web Audio 在线钢琴 · 振荡器 + ADSR 包络

      每个琴键 = 一个 OscillatorNode 接一个 GainNode。按下时按 ADSR 包络起音（attack→decay→sustain），松开时做释放淡出（release），所以尾巴不生硬。鼠标点、电脑键盘都能弹——A S D F G H J K 是低八度白键，W E T Y U 是对应黑键；高八度用鼠标点。首次发声前会 resume AudioContext。

      波形： 点任意琴键开始（首次点击会激活音频上下文）
      ▸ 关键代码 
      // 一按一振一包：osc 定频率，gain 走 ADSR
function noteOn(midi) {
  const t = ctx.currentTime;
  const osc = ctx.createOscillator();
  const g = ctx.createGain();
  osc.type = wave;                          // sine/square/…
  osc.frequency.value = 440 * Math.pow(2, (midi - 69) / 12);
  g.gain.setValueAtTime(0, t);
  g.gain.linearRampToValueAtTime(0.5, t + 0.01);        // A 起
  g.gain.exponentialRampToValueAtTime(0.22, t + 0.18);  // D→S 持
  osc.connect(g).connect(ctx.destination);
  osc.start(t);
  active.set(midi, { osc, g });
}

function noteOff(midi) {                    // R 释放淡出
  const a = active.get(midi); if (!a) return;
  const t = ctx.currentTime;
  a.g.gain.cancelScheduledValues(t);
  a.g.gain.setValueAtTime(a.g.gain.value, t);
  a.g.gain.exponentialRampToValueAtTime(0.0001, t + 0.35);
  a.osc.stop(t + 0.4);
}

function show(type, text, duration = 2400) {
  return new Promise((resolve) => {
    const el = render(type, text);

function withFlip(mutate) {
  const before = new Map(items.map((el) => [el, el.getBoundingClientRect().top]));
  mutate();                            // 移动占位虚框

          15 表单校验引擎 · schema 驱动的链式规则执行器
          
      
          校验逻辑全部住在 rules 这份 schema 里：每个字段一串规则，链式执行、短路返回第一条错误——表单逻辑里看不到一行 if-else。confirm 的规则里能读到 password 字段，跨字段校验也只是多一条规则的事。输入时实时校验，blur 时带抖动动画强调错误；右侧汇总面板实时反映每个字段状态，提交时统一跑一遍并聚焦第一个错误字段。「填充合法值」一键看全绿的样子。

            // schema 驱动：每个字段是一串规则，链式执行、短路返回第一条错误
const rules = {
  password: [
    { test: (v) => v.length > 0, msg: '密码不能为空' },
    { test: (v) => v.length >= 8, msg: '密码至少 8 位' },
    { test: (v) => /[a-zA-Z]/.test(v) && /\d/.test(v), msg: '需包含字母和数字' },
  ],
  // 规则里能读到其他字段 → 跨字段校验
  confirm: [{ test: (v) => v === form.password.value, msg: '两次不一致' }],
};

function validateField(name) {
  for (const r of rules[name]) {
    if (!r.test(form.elements[name].value)) return r.msg;  // 短路
  }
  return '';
}
