Cesium × Three 融合 方案 B · 单 Canvas 同上下文

      

        同一张 canvas、同一个 WebGL2 上下文：Cesium 先画地球，Three 不清颜色、只清深度，把精细模型叠上去。
        相机每帧做一次 syncCamera：位置/视线/上方向三个点从 ECEF 转到 ENU 局部系，再经轴系变换 (e, u, -n) 重建 Three 相机。
        模型放在以杭州为原点的 ENU 坐标系里，经纬度→局部的换算全在页面里手写。
        要联网（拉 Cesium 引擎与 OSM 底图）；也可先本地跑：把 Build/Cesium 拷进 public/cesium，页面会优先用本地包。

积雪 · CustomShader 天气特效的正规接口

      

        Cesium 给 3D Tiles 和 glTF 模型留了一个官方外挂口子：CustomShader。不用改引擎、不用改 glb，
        只要挂一个 fragment shader，就能按法线朝向往朝上的面上糊雪 —— 立面留原色，屋面和地面盖白，
        再叠一点高度加成（高处雪更厚）。这正是数字孪生里积雪、水淹、楼层剖切、热力染色共用的一套模式：
        拿位置/法线算出一个 mask，再 mix 材质。
        这里的场景是自己生成的 glb 小城（83 栋楼 + 地面，998 个三角形，无第三方资产、无许证问题）；
        CustomShader 挂 Cesium3DTileset 和挂 Model 是同一套写法，区别只是数据源。
        另外实测踩到一个 1.119 的坑：uniforms 和 varyings 一旦共存，uniform 就不上传——所以这个 demo 把参数直接烘进 shader 源码（见下方代码注释）。
        要联网拉 Cesium 引擎和底图。

// 挂到 3D Tiles / glTF 模型上：一份 shader 搞定天气与专题
// ⚠️ 实测坑（Cesium 1.119 + Model）：uniforms 和 varyings 一旦共存，uniform 就不上传。
// 所以把厚度阈值/颜色直接烘进 shader 源码，参数变了重建 shader（小 shader，重建很便宜）
const shader = new Cesium.CustomShader({
  varyings: { v_upMC: Cesium.VaryingType.VEC3 },
  vertexShaderText: `
    void vertexMain(VertexInput vsInput, inout czm_modelVertexOutput vsOutput) {
      v_upMC = vsInput.attributes.normalMC;  // fragment 拿不到 normalMC，只能自己传
    }`,
  fragmentShaderText: `
    void fragmentMain(FragmentInput fsInput, inout czm_modelMaterial material) {
      float up = normalize(v_upMC).y;                  // glTF 是 Y 轴朝上：1=屋顶 0=立面
      float th = 0.48;                                 // 由「厚度」滑杆烘进来：厚度↑ th↓
      float mask = smoothstep(th, th + 0.10, up);
      material.diffuse  = mix(material.diffuse, vec3(0.93, 0.96, 1.0), mask);
      material.emissive = mix(material.emissive, vec3(0.93, 0.96, 1.0) * 0.22, mask);
    }`,
});

tileset.customShader = shader;   // 或 model.customShader = shader
// 参数变了就重建一个 CustomShader 挂回去（uniform 路线在新版本里再换回来）
