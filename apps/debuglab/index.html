为什么卡：Content Download 分流法 定位思路

看 Network → Timing 里 Content Download 是否有值。
有值（数据已下完）→ 与后端/网速无关，前端 JS 处理太久：遍历、渲染、死循环。
无值 → 后端接口 / 网关 / 网络问题。
前端侧三板斧：分页减量 → gzip 压缩 → Chrome Performance 的 Call Tree 定位耗时方法；渲染瓶颈上虚拟列表 / 地图聚合 / Canvas 叠加层。
死循环类：Console 看 Maximum recursive updates exceeded，用注释法逐段排查（min>max、无用的 watch 回调都会中招）。

现象 Symptoms HTTP

下载 xlsx 触发两次请求，中间夹一个 flash.js（或 build.js）。
注入脚本篡改下载逻辑 → 重复请求、白页、广告跳转。
F12 Network 瀑布流里看到多余脚本，响应体被加了 <script>。
改浏览器设置禁用脚本只能自测；不能要求每个用户改浏览器，不是最终解法。

防护 Fixes HTTPS

上 HTTPS + HSTS（根本解）：加密后中间节点无法篡改响应体。
CSP 内容安全策略：script-src 白名单 + nonce，挡未授权脚本。
SRI 子资源完整性：静态资源加 integrity 哈希，被改则拒绝加载。
服务端校验响应体、针对注入特征拦截 —— 治标不治本。
关键认知：这类问题前端代码本身没问题，根在明文传输链路。一键止血是 HTTPS，长期靠 CSP+SRI 纵深防御。

坑 1 Dynamic require of "path"

报错：Dynamic require of "path" is not supported

原因：vite 3.1.x 不支持 commonJS 动态 require。修复：改 ESM 具名导入。

const path = require('path') import { resolve } from 'path' // ✅ ESM

pnpm 场景还要注意幽灵依赖：未声明的包 import 不到，需显式 pnpm add。

坑 2 Failed to resolve router-view

报错：Failed to resolve component: router-view

原因：app.use(router) 放在了 mount 之后，挂载时路由组件还没注册。

const app = createApp(App) app.mount('#app') app.use(router) /* ✅ 顺序要对 */ app.use(router) // 先注册 app.mount('#app') // 后挂载

vue3 + vite + pnpm 标准起手 checklist

# 1. 建项目（pnpm） pnpm create vite@latest my-app # 选 vue-ts cd my-app && pnpm install # 2. 路由（显式装，避免幽灵依赖） pnpm add vue-router@4 # 3. main.ts：先 use 后 mount import { createApp } from 'vue' import router from './router' createApp(App).use(router).mount('#app') # 4. vite.config 用 ESM 导入 path import { resolve } from 'path'
pnpm 核心差异：严格隔离、无幽灵依赖（未声明的包访问不到）、符号链接 + 硬链接 store。装 vue/vite 插件要按需 pnpm add -D，留意 peer 依赖警告。
