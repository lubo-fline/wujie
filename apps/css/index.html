animation-fill-mode 四种模式

同一条动画、同一次播放，只有填充模式不同。注意观察「播放前」和「播放后」那一刻：元素是停在原地，还是保持着动画里的某一帧。

none（默认）
forwards
backwards
both
.box { animation: slideAndFade 1.6s ease-in-out 0.4s; } .none { animation-fill-mode: none; } /* 前后都不留帧 */ .forwards { animation-fill-mode: forwards; } /* 结束后停在最后一帧 */ .backwards { animation-fill-mode: backwards; } /* 延迟期间先套用第一帧 */ .both { animation-fill-mode: both; } /* 两头的帧都保留 */

02 两个动画同时作用，fill-mode 会打架

左边：位移用 forwards、透明度用 none。动画一结束，位移留在终点，透明度却弹回初始态——结果是一个「已经跑到终点、却还亮着」的方块。右边两个都用 forwards，结束后才是完整终态。

两个都 forwards（正确）

03 reverse 之后，forwards 保留的是「视觉起点」

动画加了 reverse 反向播放：视觉上从右往左。但关键帧还是原来的方向——所以 forwards 保留的「最后一帧」其实是视觉上的起点。反直觉，但符合规范。下面两个都反向播放，一个 forwards 一个 both。

reverse + forwards
reverse + both
animation: revMove 1.4s ease forwards reverse; /* 停在视觉起点 */ animation: revMove 1.4s ease both reverse; /* 延迟期就套用视觉起点 */
04 无限循环时，fill-mode 只在延迟期有用

两圆都是延迟 1s、无限循环的脉冲。区别只在延迟那 1 秒里：none 显示元素的原始样式，backwards 先套用第一帧（缩小的暗圆）。循环一旦开始，两者完全一样——因为「结束后」这个时刻永远不来。

infinite + none
infinite + backwards

值延迟期间用什么帧结束后用什么帧什么时候用
none元素自身样式元素自身样式 循环动画、或用 JS 控制最终态
forwards元素自身样式最后一帧 入场动画要停在终点（最常用）

三条经验：
· 入场动画一律 both，几乎不会错；
· 一个元素挂多个动画时，逐个检查 fill-mode，别只写第一个；
· 用 reverse 或 alternate 时，先想清楚「视觉上的起点」对应哪个关键帧。

04 真相二：backwards + reverse，一开场就站在终点

反向播放时，关键帧的「第一帧」是 100%。所以 backwards 会让元素一开始就套用 100% 的样式：直接在右边、黄色。然后向左走，结束时突然跳回原位、变红。左边是 backwards，右边是 forwards 对照。

05 真相三：alternate 播两次，forwards 停在起点

方向设为交替、播放 2 次：第一次从 0% 走到 100%，第二次从 100% 回到 0%。所以「最后一帧」其实是 0%——forwards 停在左边、绿色。这就是原文表格里那一列的真意：末帧是哪一帧，取决于方向和次数。

alternate ×2 + forwards
alternate ×2 + none（弹回原点）

02 让它转起来：@property 才是关键

conic-gradient 的 from 吃一个角度值，但自定义属性默认只是「字符串」，浏览器不知道怎么在 0deg 和 360deg 之间插值——所以动画会直接跳。用 @property 把它注册成 <angle> 类型，它才变回真正的数字，才能一帧一帧地转。一行声明，决定这条光能不能动。

指针移到这张卡上

默认自动旋转。切到「跟随鼠标」后，光点会绕着你指针的方向跑，右上角实时显示当前角度。

angle 0°

03 落地时的三个坑
坑 1 · 只写 conic-gradient　出来的是整片扇形，不是光束。必须有 mask 相减；或者用「底层渐变 + 内层实心元素盖住中间」的土办法，代价是要多一层 DOM。
坑 2 · 忘了 @property　角度就是动不了。transition: --a .3s 写一百遍也没用，因为未注册的自定义属性不参与插值。
坑 3 · 用 box-shadow 做光　每帧重绘整块阴影，几张卡一起动就掉帧。锥形渐变 + mask 只改一个角度值，开销小得多；要更省就把 will-change: opacity 加在伪元素上，别加在卡片本身（会白建合成层）。

01 容器查询：组件看自己的容器，不看屏幕

同一张卡片，代码一行没改，放在窄容器里竖排、中容器横排、宽容器多出一段摘要——布局跟着「它住多大的房子」变，而不是跟着用户屏幕变。媒体查询做不到这件事，因为组件不知道自己被塞进了多宽的栏位。

01 锚点定位：tooltip 自动贴住按钮Chrome 125+

左边按钮悬停出 tooltip，右边按钮点开弹层——定位代码里没有一个像素坐标：声明「我是锚」，弹层声明「我贴着谁、贴哪一侧」，剩下（跟随滚动、屏幕边缘翻转）浏览器全包。以前这套逻辑要几十行 JS 手算 getBoundingClientRect。

我没写一行定位坐标，只声明了「贴在锚的上方，放不下就翻到下面」
锚点 + Popover
我贴在按钮下方，滚动页面我会跟着走，屏幕边缘我会自动换边。

/* 锚：起个名字 */ .btn { anchor-name: --tip; } /* 弹层：声明跟随关系，不写一个坐标 */ .tip { position: fixed; position-anchor: --tip; position-area: top; /* 贴锚的上方 */ position-try-fallbacks: flip-block; /* 放不下自动翻面 */ } /* popover 用 HTML 属性就开：popovertarget="id" */
01 masonry 瀑布流：JS 算高度的时代要结束了

右边所有浏览器都能跑（多栏 columns 的近似版）；左边 grid-template-rows: masonry 是真正的提案语法——子项自动按列填充最短的那条，不再需要 JS 量高度再绝对定位。左边没效果说明你的浏览器还没开 flag，本身就是一个活教材：提案从诞生到默认可用要很多年。

① grid + masonry（提案中）
② columns 多栏（今天就能用）
/* 提案版：真瀑布流，子项自动去最短的列 */ .ms { display: grid; grid-template-columns: repeat(3, 1fr); grid-template-rows: masonry; /* 就这一个词 */ } /* 兼容版：多栏布局，从上往下再折列（阅读顺序不同） */ .ms { columns: 3; column-gap: 6px; } .ms > * { break-inside: avoid; }
01 原生 dialog：弹层这件事浏览器早想包了

<dialog> + showModal()：焦点圈定、Esc 关闭、遮罩层全是白送的。::backdrop 想毛玻璃就毛玻璃，[open] 上的动画选择器管进出。右边这个弹层看起来要一个 UI 库，其实 CSS 只写了四行。

我是原生 dialog

试一下：按 Esc 能关我，Tab 焦点跑不出我的范围——这些以前都是「弹层组件」卖给你的功能。

毛玻璃遮罩 + 入场动画

遮罩是 ::backdrop 伪元素：backdrop-filter 十行不到。入场动画写在 dialog[open] 上，一行 keyframes。

 const dlg = document.querySelector('#dlgGlass'); dlg.showModal(); // 一行打开（自带遮罩、焦点圈定、Esc） /* 遮罩：毛玻璃就一个属性 */ dialog::backdrop { background: rgba(8,12,28,.35); backdrop-filter: blur(10px); } /* 入场动画：[open] 匹配即可 */ dialog[open] { animation: dlg-in .28s ease; }
